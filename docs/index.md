## Custom Project

### Dataset

- The dataset is data\sales.csv.
- It contains transactions of textbooks from an online commerce website.
- Fields included in each record are order_id, datetime, region_id, currency_code,product_id, unit_price, quantity, is_online,customer_id, is_new_customer, device_type,payment_method, referral_source, discount_code, and customer_note.
- I used the original sales dataset for this project.
- The regions.csv and currencies.csv datasets are used for enrichment.

### Data Contract

The data contract is defined in data_contract_reed.py.
Required fields are defined in the variable SALES_REQUIRED_FIELDS.

SALES_REQUIRED_FIELDS: Final[list[str]] = [
    "order_id",
    "datetime",
    "region_id",
    "currency_code",
    "product_id",
    "unit_price",
    "quantity",
    "is_online",
    "customer_id",
    "payment_method",
]

A message not containing one or more of these fields is not valid and will be rejected.
In the future, the function validate_sale_record in data_contract_case.py can be used
to validate fields.

### Kafka Messages

- The producer iterates through sales.csv and sends a single row as a message.
- The Kafka topic used is streaming-03-analytics-reed.
- The message key used was region_id.
- No message fields were changed, but a new field titled currency_subtotal was created,
  which is described below under **Data Engineering and Enrichment**.

### Consumer Validation

The consumer validates required fields listed in SALES_REQUIRED_FIELDS.
When a message is accepted, it is written to data\output\consumed_sales.csv.
When a message is rejected, it is logged and the consumer begins processing the next message. Validation is important for ensuring that processed data does not contain missing fields. Missing fields can corrupt running totals that are calculated as messages are processed and cause enrichment to fail.
